# Очередь SAST: правило, файл, строки и обработка

19 октября 2026. Проект поднят на UI 5173/API 8005 с прежней рабочей БД. Перед запуском и обновлением API сделаны резервные копии; init_db дважды проверен на копии с точным сохранением всех старых строк. Схема БД не менялась.

## Контракт и неизменяемость

В trace.intake/1 добавлено необязательное `analysis`:

```json
{"kind":"sast","scanner":"semgrep","location":{"path":"src/api.py","startLine":12,"endLine":15}}
```

Это нормализованное наблюдение, заявленное источником, а не оригинальный JSON Semgrep. Все прежние поля отчёта, ссылка на доказательство и её SHA-256 обязательны. Источник должен иметь module=appsec, актив — kind=repository. Правило хранится в прежнем ruleId. Путь до 512 символов — относительный к репозиторию, с `/`; абсолютные/Windows/UNC пути, `..`, пустые/`.` сегменты, управляющие символы и обратные слеши отклоняются. Строки — строгие целые 1–10000000; endLine не меньше startLine. Неизвестные поля, исходный код и неподдерживаемый scanner в analysis не принимаются. Сам файл не загружается, путь не используется для чтения диска или сетевых запросов.

Analysis включён в неизменяемый payload и его SHA-256. Повтор sourceId/externalId с тем же телом идемпотентен, изменение файла/строк получает 409. Новые поля не добавляются в старые отчёты; exclude_none сохраняет их канонические суммы. Типизированный отчёт проходит тот же intake, в том числе при подписанной доставке; доверие остаётся not_attested. Наличие scanner=semgrep не доказывает запуск Semgrep.

## API и интерфейс

GET `/api/v1/platform/module-results?analysisKind=sast&ruleId=RULE&path=FILE&offset=0&limit=50` выбирает только SAST-наблюдения. Правило и путь фильтруются точным равенством до пагинации. Сортировка receivedAt desc/id; прежний API без новых параметров сохраняется. Действуют прежние workspace/org scope и роли; импорт admin, чтение viewer/analyst/admin, решения analyst/admin. JSON-фильтры не индексировались: производительность больших историй ещё не измерена.

Во вкладке SAST добавлена отдельная очередь пространства, независимая от выбранной legacy AppSec-проверки: до 50 наблюдений на страницу, фильтры правила/файла, явное отсутствие данных/ошибки, безопасный шаблон и импорт одной записи. Сначала зарегистрируйте источник appsec и актив «Репозиторий» через «Активы и модули», затем замените все placeholders фактическими значениями отчёта. Не вставляйте секреты или исходный код. Заполнение шаблона не запускает сканер.

Карточка показывает rule/location и использует существующие workflow, причины, автора, версию, историю, evidence/provenance и ручные связи повторной проверки. Решение хранится отдельно; ручное закрытие не подтверждает исправление. Названия активов ограничены загруженной первой страницей реестра; при отсутствии имени показан ID. Пагинация offset не является закреплённым снимком: новые импорты во время просмотра могут сдвигать страницы. Повторные проверки по-прежнему ручные, не доказательство совпадения кода/коммита или устранения причины.

## Проверка и границы

Пять новых API-тестов: roundtrip/сумма/идемпотентность/конфликт расположения, пути/строки/extra/scanner, источник/актив/роли/изоляция, точные фильтры/пагинация/исключение legacy, чтение без изменения отчётов и аудита. Прежние отчёты и прочие модули не классифицируются как SAST по догадке.

Через браузер на отдельной QA-базе проверены импорт нормализованной записи `src/qa_api.py`, строки 12–15, отсутствие generic-отчёта в SAST, пустой и точный фильтры, карточка и сохранение «В работе» с причиной, версия 1/история и сохранность после перезагрузки. QA-данные не вносятся в рабочую установку. Прошли 202 теста общего набора (324,008 с), TypeScript, production build и 7 API-client checks. Все 42 таблицы рабочей БД сохранены, 13 прежних контрактов находок проверены через 5173.

Это первый ручной контур SAST. Автоматическое преобразование полного JSON Semgrep, отдельный исполнитель SAST, rule catalog, commit/diff/code view, автоматическая группировка occurrence и подтверждение исправления пока не реализованы. Старые CVE-находки не выдаются за результаты всех SAST-правил. Далее — ограниченный адаптер оригинального отчёта Semgrep и привязка к проверяемой версии кода.
