# Этап 35: SAST в постоянной очереди Job

Веб-форма SAST принимает только ID разрешённой серверной цели и полный Git commit (40/64 hex). Worker использует локальный executor этапа 34 и автоматически принимает пакет результатов. Создание фиктивной общей AppSec Scan не требуется.

## Настройка

`TRACE_SAST_TARGETS_FILE` — абсолютный путь к JSON-массиву, максимум 64 КиБ и 20 уникальных целей. Без настройки список пуст и запуск отключён. `TRACE_SAST_EXECUTABLE` задаёт доверенный установленный executable, по умолчанию semgrep. Нужен Git.

Пример элемента массива (ID источника и repository asset должны существовать в указанном пространстве):

```json
{"id":"local-repo","name":"Локальный репозиторий","workspaceId":"default","sourceId":"SOURCE_ID","assetId":"ASSET_ID","repositoryPath":"C:/repos/project","rulesPath":"C:/trace/rules.yaml","timeout":120}
```

Пути абсолютные; timeout 1–600 секунд. Браузер не передаёт команды или пути. Ответ GET targets не раскрывает файловые пути; некорректная конфигурация возвращает 503. Рабочая установка оставлена без целей: реальный Semgrep пока не установлен.

## Контракт и гарантии

GET `/api/v1/platform/sast/targets`, GET/POST `/api/v1/platform/sast/jobs`, GET `/api/v1/platform/sast/executions`. Чтение scoped; создание требует admin. Используются общие admission limits, dedup активных заданий, outbox, claim/attempt, heartbeat и отмена queued. Права инициатора, источник, repository asset и хеши конфигурации/правил проверяются перед выполнением и после процесса перед сохранением. Commit закреплён в задании и сверяется с execution receipt.

SastExecution, SemgrepBatch, результаты и аудит сохраняются одной транзакцией. Хеш свидетельства связывает job/attempt/batch и хеш пакета. Scope и неизменяемость защищены ORM, включая bulk-операции. При потере финального статуса существующее согласованное свидетельство позволяет завершить Job без повторного запуска сканера. Неопределённый running автоматически не перезапускается. Свидетельство сохраняется после retention метаданных Job; ссылки проверяются при создании, внешнего ключа к удаляемому Job нет.

UI показывает последние 20 заданий и свидетельств; обновление ручное. Отмена выполняющегося процесса и расписания не реализованы. Свидетельство не является внешней аттестацией, доказательством покрытия, сетевой изоляции или истинности находки. Ограничения Git snapshot/process/output этапа 34 сохраняются.

## Проверки

8 новых тестов: права/scope, закрытые пути, disabled default, dedup/cancel, capacity, отказ при изменении правил/прав до и после процесса, атомарный rollback, recovery без перезапуска, immutable receipt и сохранение после Job retention.

На изолированной БД через браузер создан Job, выполнен worker, автоматически приняты пакет и одна находка. Использованы настоящий Git и явно тестовый процесс вместо Semgrep. Закреплённый файл проанализирован, dirty worktree сохранён. Это проверка интеграции, не реальное SAST-сканирование. Рабочие 44 таблицы и 13 находок не изменены; рабочие targets/executions пусты.

Далее: проверить установленный настоящий Semgrep на согласованной локальной цели и расширять управление правилами/запусками. CI/CD, DAST, SCA остаются отдельными направлениями с собственными ограничениями.

Итог этапа 35: окончательный общий прогон — 228 тестов, OK (378,312 с). Восемь новых тестов отдельно — OK. TypeScript/build и 7 API-client checks — OK; браузерный Job → worker → batch → находка проверен на изолированной БД.
