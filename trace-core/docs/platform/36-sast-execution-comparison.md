# Этап 36: сравнение выполнений SAST

Вкладка SAST позволяет выбрать базовое и новое серверные выполнения и показать различия их пакетов. Это сравнение наблюдений, а не автоматическое подтверждение исправления.

## API и проверка оснований

GET `/api/v1/platform/sast/executions/{execution_id}/compare?baselineId=...` доступен читателям выбранного пространства. Несуществующие и чужие execution ID не раскрываются (404; отсутствие доступа к пространству — 403/404). Одинаковые ID и обратный порядок — 422. Различающиеся target/config/rules/executor/source/repository — 409. Базовое выполнение должно предшествовать новому по серверному времени завершения и ID.

Перед сравнением проверяются scoped-свидетельства, их канонические SHA-256 и связи job/attempt/batch; затем каждый result, manifest, документные хеши и канонический хеш BatchInput. Повреждённое или неполное основание даёт 409. Сравнение работает после retention метаданных Job, пока сохранены неизменяемые свидетельства и пакеты. Текущая настройка allowlist и наличие сканера для чтения истории не требуются.

Сопоставление: точные ruleId, repository path, startLine, endLine. Смена строк — другое наблюдение. Повторения одного ключа сгруппированы, все result ID сохранены в строке. Счётчики относятся к уникальным ключам, максимум 100 результатов в каждом исходном пакете и 200 строк сравнения.

Состояния: `appeared` (появилось), `repeated` (повторилось), `not_observed` (не наблюдается в новом отчёте). Возвращаются оба commit, состояния отчётов, ID связанных результатов. `coverageVerified=false`, `remediationVerified=false` всегда. Пустой, partial или unknown отчёт не доказывает исправление или безопасность. Workflow/retest записи не изменяются, scanner не запускается, новые сущности/таблицы не создаются.

## Интерфейс и ограничения

Раскрываемый блок «Сравнение выполнений SAST» расположен рядом со свидетельствами. Выбираются два из последних 20 выполнений пространства. API допускает более старые известные ID. Результат сбрасывается при смене выбора. Без двух выполнений показано объяснение без активной кнопки.

Сравнение строгое: даже изменение имени цели/timeout меняет configSha256 и отклоняет пару. Совпадение настроек и executor не доказывает одинаковую бинарную версию Semgrep, состав правил с внешними зависимостями или покрытие. Сопоставление при переносе строк и автоматическое закрытие находок не реализованы. Независимая аттестация и настоящий Semgrep в рабочей установке по-прежнему отсутствуют.

## Проверка

5 новых тестов: появление/повтор/сдвиг строк, partial/empty без утверждения об исправлении, несовместимая конфигурация, scope/порядок/404, повреждённое свидетельство. TypeScript, production build и 7 API-client checks прошли.

На изолированном стенде выполнены два настоящих Git snapshot с явно тестовым scanner process, затем сравнение проверено через форму браузера: появилось 1, повторилось 0, не наблюдается 1. Это проверка интеграции, не реальное сканирование Semgrep. Рабочие 44 таблицы и 13 прежних находок сохранены; рабочие targets и executions пусты.

Следующий этап: полноценная проверка настоящего Semgrep на разрешённой локальной цели и дальнейшая связь результатов с исправлениями/повторными проверками. DAST/SCA и остальные модули развиваются отдельно по общей дорожной карте.

Итог этапа 36: общий backend-набор — 233 теста, OK (386,758 с); TypeScript, production build, 7 API-client checks и браузерное сравнение двух тестовых выполнений — OK. Рабочая установка запущена, отдельный QA остановлен.
