# Отдельные вкладки CI/CD, SAST, DAST и SCA

По уточнению пользователя добавлены самостоятельные маршруты `#view=cicd`, `#view=sast`, `#view=dast`, `#view=sca`, пункты бокового меню, команды поиска, заголовки и переходы между направлениями. Параметры workspace/scan сохраняются существующей навигацией. Страницы доступны без выбранного scan; отсутствие данных и ошибки API показаны явно. Общее ядро проектов, прав, находок и аудита сохранено. Это первый рабочий интерфейс направлений, а не завершение всех четырёх интеграций.

SAST и SCA читают текущее наличие инструментов из `/platform/modules`, отдельно показывают `scannerResults` выбранной проверки по её role. SAST — Semgrep, SCA — Trivy/Grype/OSV. PATH означает только наличие бинарника, не успешный запуск. Отсутствие scannerResults не трактуется как успешное выполнение или отсутствие уязвимостей. Демонстрационная проверка явно подписана. Общая очередь AppSec не выдаётся за отдельную очередь SAST/SCA; SCA имеет рабочий переход к зависимостям/SBOM. Общий запуск и история остаются в существующем разделе проверок: запуск только одного направления пока не реализован.

CI/CD читает источники пространства и GET `/scans/{id}/policy`: оценка вычисляется по текущей политике и текущим находкам, не является сохранённым историческим решением CI. При смене выбранного scan старая оценка не отображается как новая. Администратор использует прежний SourceWebhookPanel: состояние ключа, число принятых доставок, endpoint и настройки env secret_ref. Значение секрета в браузер не попадает. Viewer/analyst не получают административную форму. Включённый приём сам по себе не означает работающий pipeline. Регистрация/импорт и настройки политики доступны переходами к существующим формам.

DAST имеет отдельный экран с текущим статусом: исполнитель отсутствует, результатов и покрытия нет, запуск не предлагается. Указаны необходимые условия реализации и переход к проектам. Новых сетевых сканирований, фиктивных запусков/результатов и автоматических внешних подключений нет.

Проверка: TypeScript, production build и 7 проверок API-клиента прошли. В живом браузере открыты все четыре маршрута, переходы между ними и переход через боковое меню, прочитано состояние CI без сохранения настроек. Рабочая установка честно показывает отсутствие четырёх бинарников и отдельных scannerResults в демо-проверке; CI оценка — blocked/exit 1, одна блокирующая из 13 находок, подписанный приём выключен, доставок 0. Backend и схема БД не менялись; общий backend suite здесь повторно не запускался (предыдущий этап: 197 тестов).

Следующий шаг — отдельная рабочая очередь SAST с rule/location, затем управляемое выполнение отдельных направлений. DAST требует отдельного исполнителя и согласованной цели; реальный внешний CI требует настройки pipeline и проверки доставки.
