# Исправление основного интерфейса: подключение актуального API

Причина сообщения «API платформы ещё не обновлён»: интерфейс 5173 обращался к давно запущенному процессу 8000. Код платформы был реализован и проверен на изолированных стендах, но основной процесс оставался старым. Это реальный разрыв между подготовкой кода и его подключением в пользовательском экземпляре, а не отсутствие данных и не ошибка браузера.

## Текущий рабочий маршрут

Пользовательский интерфейс: http://127.0.0.1:5173/

Его Vite proxy теперь по умолчанию обращается к актуальному API http://127.0.0.1:8005/. Явный VITE_API_TARGET по-прежнему имеет приоритет; в текущем frontend-процессе он не был установлен. Активная БД нового API — C:/Users/vlad/trace-core/trace_api/trace-platform.db. Это проверенная мигрированная копия прежней рабочей БД, без импорта тестовых fixtures.

Старый процесс 8000 не удалось остановить: ОС вернула WinError 5 при завершении подтверждённого процесса. Поэтому исходная trace_api/trace.db осталась нетронутой, а переключение выполнено через новый порт и отдельную мигрированную рабочую копию. Порт 8000 больше не является источником данных для 5173. Пользоваться двумя API для записи одновременно нельзя: исходная и новая БД после переключения развиваются независимо. При необходимости старый процесс следует закрыть из той пользовательской сессии/терминала, в которой он был запущен.

## Сохранность данных

Перед переключением создана SQLite backup, миграция дважды проверена на копии, сохранность всех старых строк проверена по прежним столбцам. PRAGMA integrity_check успешен. Перед копированием проверено отсутствие активных фоновых заданий и rescan.

В новом экземпляре сохранены 1 проект, 1 проверка и 13 находок, прежний пользователь root и настройки. Все прежние строки 6 исходных таблиц совпадают. Добавлено только основное пространство и служебные структуры миграции; тестовые пространства, команды и задания не переносились. Счётчики нового экземпляра: workspaces=1, teams=0, scan_jobs=0.

Backup: work/primary-trace-backup-20261018-032559.db в папке этой работы Codex. Файл содержит рабочие данные и не включён в пользовательские outputs. Исходная БД также сохранена на прежнем месте. Режим авторизации не ослаблялся: как и раньше, обязательный вход выключен, статического токена не было; API слушает только 127.0.0.1. Остальные настройки окружения исходного процесса сохранены при текущем запуске без вывода их значений.

## Проверка через реальный адрес

Через 5173 успешно получены /api/v1/workspaces, /api/v1/access/context и /api/v1/projects. В браузере проверены «Пространства и команды» и «Организация и доступ»: прежнее сообщение об устаревшем API отсутствует, отображаются основное пространство, прежний Administrator/root и реальные формы управления. Старый scan-8f21a3c с 13 находками загружается. Изменения прав, выдача credentials и создание тестовых ресурсов в рабочем экземпляре не выполнялись.

Снимки TRACE-primary-workspaces-fixed.png и TRACE-primary-access-fixed.png сохранены в outputs. git diff --check успешен. Бизнес-логика этого исправления не менялась; применена ранее проверенная версия API.

## Повторный запуск

Если актуальный API остановлен, из C:/Users/vlad/trace-core выполнить:

```
.\.venv\Scripts\python.exe run_platform.py
```

Лаунчер выбирает trace_api/trace-platform.db и порт 8005. Он не создаёт новую пустую БД вместо пропавшей рабочей копии. Режим авторизации и остальные настройки наследуются из окружения; при самостоятельном запуске следует сохранить нужные настройки интеграций. Старый run.py сохранён для совместимости и не является новым лаунчером этой рабочей копии.

После переключения достаточно обновить страницу 5173; если в давно открытой вкладке остался старый экран, выполнить Ctrl+F5. Для дальнейшей работы используется новая рабочая БД, не тестовые стенды 8001/8003/8004.
