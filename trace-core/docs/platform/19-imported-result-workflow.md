# Обработка импортированных результатов

Для module_results добавлено отдельное состояние обработки в module_result_workflows. Исходный payload, SHA-256, источник и время наблюдения не переписываются. По умолчанию API возвращает виртуальное состояние new/revision=0, не создавая строки при чтении.

## Операции

GET `/api/v1/platform/module-results/{id}` возвращает результат, текущее workflow и последние 100 изменений workflow из аудита. Списочная выдача также включает workflow; загрузка состояний выполняется одним запросом по выбранной странице. Имеющийся фильтр assetId теперь доступен в UI.

PUT `/api/v1/platform/module-results/{id}/workflow` принимает expectedRevision, status, assignee, dueDate и note. Неизвестные поля отклоняются. Состояния: new, in_progress, resolved (ручное закрытие), accepted_risk. Ответственный — текст до 128 символов, комментарий — до 4000. Это назначение работы, а не выдача доступа пользователю.

Менять состояние могут аналитик и администратор с доступом к пространству. Наблюдатель читает. Сервисные аккаунты пока к этим маршрутам не допущены. Чужие и отсутствующие идентификаторы дают 404.

Ручное закрытие и принятие риска требуют непустой причины. Принятие риска дополнительно требует даты пересмотра позже текущей даты UTC. Это ручное решение, не подтверждение исправления; нужна повторная проверка и новый отчёт. Автоматического пересмотра/отзыва решения, уведомлений о сроке и SLA scheduler на этом этапе нет.

## Конкурентность и история

expectedRevision обязателен и проверяется под блокировкой источника, включая первую запись workflow. Устаревшая версия получает HTTP 409. Из двух одновременных изменений одной версии проходит одно, поэтому правки не перетираются молча. В UI черновик при ошибке остаётся; кнопка обновления состояния явно сбрасывает его. Изменение без фактических отличий не увеличивает версию и не пишет аудит.

Новая версия, before/after и серверный actor сохраняются вместе с workflow в одной транзакции PlatformAudit (module-result.workflow). Ошибка аудита откатывает изменение. В истории сохраняются статус, ответственный, срок и причина, но не переписывается техническое evidence. Изменять уже принятые решения можно новой версией, в том числе возвращать результат в работу.

Выключение источника останавливает intake, но не блокирует работу с уже принятыми отчётами. Повтор старого неизменённого импорта возвращает текущее workflow, сохраняя исходный SHA-256 и payload. Внешние действия, сканирование, отправка сообщений и AI не запускаются.

## Проверка

Добавлено 6 тестов: чтение без записи и история, исходный отчёт без изменений, конкурентные правки/409, причины и дата риска, права и область, откат аудита, обработка после отключения источника и no-op. Полный набор — 116 тестов; TypeScript, build и 7 API-client smoke проверок проходят.

В браузере на изолированной БД (порт 8007) тестовый результат переведён в работу, назначен qa-analyst и сохранён комментарий. После перезагрузки сохранены версия 1 и история. Контрольная сумма исходного импорта проверяется отдельно. Основной API обновлён с резервной копией; тестовые отчёты в рабочую базу не импортировались.

Ограничения: общий снимок аудита ограничен 100 последними изменениями, экспорт полной истории пока отсутствует; нет отдельной сущности исключения/согласования или связи retest с новым отчётом; интеграция статуса в AppSec gate не выполняется. PostgreSQL в живом окружении не проверялся. Следующий этап — явная связь результата с повторной проверкой и решением, сохраняя историю наблюдений.
