## Работающие контуры

1. AppSec: существующие Project/Scan/Finding, SBOM/VEX, triage, release gate и scannerResults. Демо-проверка явно помечена. SCA wrappers поддерживают Trivy/Grype/OSV; наличие wrapper не доказывает наличие и запуск бинарника.
2. Организация и рабочие пространства: пользователи, команды, grants, сессии, scoped service accounts, настройки/secret_ref. Single-install; второй tenant/SSO не реализованы. Рабочая локальная установка не переведена в новый режим авторизации без запроса пользователя.
3. Общая очередь: durable Job/Attempt/outbox, admission/capacity, heartbeat, queued cancel, recovery по сохранённому результату без слепого повторного запуска, операторский retention. Планировщик и running cancel остаются открытыми.
4. Результаты и происхождение: ручной/подписанный intake, workflow/retests, небольшие immutable evidence files, SHA-256, первичные receipts и доставка. Это не независимая аттестация источника.
5. Поставка: repository → build(commit) → artifact(digest) → deployment(environment) и immutable контекст результата. Внешняя подпись артефактов/Sigstore не подключены.
6. Инфраструктура: история inventory, свежесть, complete/partial/error, сравнение снимков и сверка. NetBox CLI испытан локально; реальной CMDB/cloud учётной записи нет.
7. SAST: rule/path/line queue, Semgrep JSON adapter, batch intake, локальный Git snapshot runner, web Job allowlist и execution comparison. Настоящий Semgrep не установлен; Git+явно тестовый процесс подтверждают интеграцию, но не заменяют реальный сканер.
8. Работа команды: выбранные оператором event/detection/incident/risk/control/exception/task с отдельными типами и состояниями, связями к активам/находкам/результатам, историей, версиями и причинами. Исключения требуют другого администратора; они не меняют gate/доступ. Это case management, не SIEM и не автоматическое реагирование.

## Границы новых рабочих разделов

`security_records` — общий реестр разных типов документов с независимыми статусами, а не Finding и не поток событий. Неизменяемый исходный payload + SHA-256; изменяемое решение хранится отдельно от наблюдения. `security_changes` — append-only решения, `security_links` — неизменяемые scoped-связи с причинами. До 50 записей на странице; detail показывает до 100 связей каждого направления и 100 последних решений. Полная история сохраняется в БД.

API `/api/v1/platform/security-records`: list/search/kind/status, create с необязательным externalKey для идемпотентности, schema, detail, decision(expectedRevision), links. Viewer читает, analyst/admin создают и ведут работу, service account доступ по умолчанию закрыт. Риск принимает admin. Исключение принимает/отклоняет другой admin, срок обязателен, истечение вычисляется при чтении. Terminal approval не переписывается: нужен новый запрос. Автоматическое применение исключений отсутствует.

Для закрытия инцидента/риска, выполнения задачи или записи основания контроля требуется существующая связь с объяснением. Это минимальное проверяемое основание решения оператора, а не доказательство эффективности исправления или выполнения стандарта. Повторная проверка находки остаётся отдельным процессом. Ответственный — текстовое назначение без выдачи полномочий; срок не является измеренным SLA.

## Дополнительная проверка связности и конкурентных изменений

Из карточки существующей находки или актива можно создать связанный incident/risk/task без копирования ID. Контекст и обязательная причина сохраняются одной транзакцией. GET related возвращает до 100 scoped-записей выбранного объекта, ссылки открывают конкретную запись через `record` в URL. Запись ссылается обратно на находку; старый workflow находки не меняется.

Записи при создании, решения и добавление ссылок сериализуются по рабочему пространству до чтения revision/idempotency key. CAS expectedRevision и уникальные ограничения защищают от потерянного обновления и дубля; rollback включает историю и аудит. Тест реальной конкуренции проверяет 201/200 для одинакового ключа и 200/409 для двух решений одной версии.

Девять тестов нового контура прошли. Первичный общий прогон: 241 тест, OK; окончательный общий прогон после добавления конкурентного теста: 242 теста, OK (426,594 с). TypeScript/build/API-client checks и браузерные сценарии на изолированной БД прошли. Рабочая база содержит 47 таблиц: старые 44 и 13 находок сохранены, новые реестры в ней пусты.

Наличие полноценного реального SAST/DAST или внешних продуктов этим не заявляется.
