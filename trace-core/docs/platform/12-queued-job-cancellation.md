# Этап 2Б.2: отмена ожидающего задания

Реализована отмена durable-проверки до начала исполнения. Отмена не удаляет Job, Outbox, результаты проверок или историю; не завершает процесс worker и не выдаётся за остановку уже запущенного сканера.

## API и полномочия

POST `/api/v1/jobs/{id}/cancel` доступен администратору, как запуск проверки исходников. Viewer и analyst получают 403, запрос без входа — 401; сервисные аккаунты не имеют scope для этого маршрута. Пространство берётся из серверного principal, автор — из разрешённого сервером actor. Поля тела запроса не задают scope и автора.

Неизвестный ID и ID другого пространства возвращают 404. Для running/completed/обычной ошибки возвращается 409 с объяснением, что можно отменить только ожидающее задание. Повторная отмена уже отменённого Job идемпотентна: возвращает тот же результат без второго события аудита.

## Атомарность

Отмена захватывает ту же строку управления очередью, что worker перед queued → running. Поэтому есть один победитель: либо Job отменён до старта и Attempt не возникает, либо worker уже захватил задание, а отмена возвращает 409. Не существует состояния «успешно отменено», в котором одновременно разрешён новый запуск конвейера.

Для отменённого Job сохраняется finishedAt, очищаются приватные params и записывается PlatformAudit job.cancelled. Эти изменения происходят в одной транзакции; ошибка записи аудита откатывает отмену. Освобождается место в лимите ожидающей очереди. Outbox сохраняется для истории, но выборка dispatcher его больше не доставляет.

Уже отправленное сообщение может физически дойти до worker после отмены. Его нельзя надёжно отозвать из всех транспортов, поэтому защита находится в БД: worker не захватывает terminal Job и не обращается к исходникам. Позднее подтверждение отправки меняет только метаданные Outbox и не возвращает задание в очередь.

## Представление состояния и совместимость БД

API возвращает status=cancelled, executionState=cancelled, terminalReason=cancelled, requiresReview=false и cancellable=false. Это отдельное состояние продукта, не ошибка движка. Для queued API добавляет cancellable=true; это признак состояния, не разрешение на действие — права всё равно проверяются сервером.

Старый CHECK таблицы scan_jobs допускает четыре значения. Чтобы не пересоздавать таблицу со ссылками от Attempt/Outbox/Heartbeat/Receipt только ради нового названия, внутренний terminal-код сохраняется как status=failed с явным result.terminalReason=cancelled. Публичный сериализатор переводит именно эту комбинацию в cancelled. Обычная failed-запись не переименовывается. Прямые SQL-отчёты должны различать terminalReason, иначе они смешают отмены с ошибками. Новая миграция схемы в этом подэтапе не нужна.

## Интерфейс

В каталоге фоновых заданий кнопка «Отменить ожидание» показывается только администратору и только при явном cancellable=true от API. Во время запроса кнопки отмены блокируются. Успех обновляет строку на «Отменено до запуска», убирает действие и при необходимости обновляет выбранное наблюдаемое задание. Ошибка отображается отдельно от таблицы. Кнопка «Наблюдать» и сохранённая история остаются доступны.

Старый API без cancellable не получает неработающую кнопку. Running с потерянным heartbeat нельзя отменить этим действием: неопределённость активности не даёт права считать процесс остановленным. Автоматический повтор не добавлен.

## Проверка

Шесть новых серверных сценариев проверяют идемпотентность, серверного автора аудита, очистку params, отсутствие Attempt, права и scope, отказ для running/completed, гонку worker с отменой, запоздалую доставку, rollback при ошибке аудита и повторное использование места в очереди. Для сканеров используются подменённые конвейеры; сторонние системы не проверялись.

TypeScript и production Vite build успешны, 7 проверок совместимости API-клиента прошли, git diff --check успешен.

Живой UI проверен на отдельном 8004 с work/cancel-ui.db. БД скопирована из прежнего изолированного стенда; занятый тестовый слот и лимит max_running=1 удерживали явно тестовое test-queued-cancel в очереди, не допуская исполнения источника. Через кнопку в браузере задание отменено. HTTP подтвердил cancelled, а прямое чтение БД — ноль Attempt и одну запись job.cancelled. Содержимое projects/scans/findings/platform_assets/platform_asset_links совпало с исходной копией. Снимок TRACE-job-cancelled.png сохранён в outputs. Стенд оставлен для просмотра; основные API и БД не обновлялись.
