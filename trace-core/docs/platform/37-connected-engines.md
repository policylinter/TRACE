# Подключённые движки — 22 октября 2026

## SCA: настоящий OSV-Scanner

Установлен официальный Windows amd64 OSV-Scanner 2.7.0 в `.tools/osv-scanner`. SHA-256 сверён с метаданными официального GitHub release. `tools/check_osv.py` запускает движок на отдельном публичном npm lockfile с lodash 4.17.20 и выдаёт `readiness.json`. Настройка TRACE использует локальный бинарник только при успешной самопроверке и совпадении хеша файла с маркером. Иначе остаётся внешний `TRACE_OSV_BIN`/PATH.

Это сетевой SCA-анализ: координаты зависимостей используются для запросов OSV, исходный код не загружается. Для закрытых окружений понадобится отдельно настроенный офлайн-режим/база; он этой проверкой не подтверждён.

Через UI в изолированной QA-базе запущено фоновое задание `449f736d96714be487a8b534c1588a4e`. Получен scan `scan-0000000-00a0f26b8e93`: пять реальных находок OSV по публичной тестовой зависимости. Статус OSV — completed; всей проверки — partial, потому что остальные движки не выполнялись. MODERATE нормализуется в medium. Версии исправления извлекаются только из соответствующего имени/экосистемы пакета.

## DAST: собственный ограниченный HTTP baseline

`GET /api/v1/platform/dast/targets` показывает настроенные цели пространства. `POST /api/v1/platform/dast/checks` принимает только targetId и требует администратора. Конфигурация: абсолютный путь в `TRACE_DAST_TARGETS_FILE`, пример — `dast-targets.example.json`.

Разрешены только явные HTTP URL 127.0.0.1 или ::1 с портом 1024–65535. Нельзя передать произвольный URL из браузера, credentials, query или fragment. Выполняется один GET, без proxy и redirects, timeout 3 секунды. Проверяются CSP, nosniff и frame-ancestors/X-Frame-Options для HTML. Исходный ответ и cookies не сохраняются. Перед сохранением повторно проверяются права автора и конфигурация цели.

Результат сохраняется как partial, даже если замечаний нет: другие маршруты, авторизация и эксплуатация не проверялись. Это не полноценный ZAP active scan. Внешние адреса этим исполнителем не поддерживаются.

Тестовый стенд: `.venv\Scripts\python.exe tools\dast_demo_app.py`, порт 8878, только loopback. `/missing` без трёх заголовков, `/secured` с ними. Это явно помеченная фикстура, а не промышленное приложение. Через UI `/missing` создал три наблюдения в `scan-0000000-0fad4d792a8b`. Unit/integration tests проверяют также чистый вариант, запрет redirect, права и изменение конфигурации во время запроса.

Для своего локального стенда укажите существующий projectId и workspaceId в отдельной конфигурации, затем запустите TRACE с `TRACE_DAST_TARGETS_FILE`. В основной установке цели автоматически не добавляются.

## CI: исполняемый SCA gate

`tools/run_sca_ci.py --scanner <путь к OSV> --source <репозиторий> --output <каталог> --threshold high` запускает OSV, проверяет структуру/покрытие и сохраняет osv.json и gate.json. Коды: 0 — покрытые пакеты без блокирующих находок; 1 — превышен порог; 2 — ошибка или отсутствие покрытия пакетов. Неизвестная серьёзность считается блокирующей.

На настоящем OSV-отчёте тестовой зависимости gate вернул 1: пять находок, две блокирующие. На lockfile публичной lodash 4.18.1, версия которой проверена через npm registry, получен код 0: один покрытый пакет, ноль находок. Для доказательства покрытия и чистого результата OSV запускается с --all-packages. Это локально подтверждённая работа gate, а не свидетельство внешнего pipeline.

`.gitlab-ci.example.yml` предназначен для репозитория TRACE: закреплён OSV 2.7.0, проверяется SHA-256 Linux binary, отчёты сохраняются в artifacts даже при блокировке. Для другого проекта перенесите нужный runner-код/нормализатор и адаптируйте пути. Подключение к вашему GitLab runner требует самого репозитория и настроек провайдера; удалённый pipeline здесь не запускался. Существующая подписанная доставка результатов остаётся отдельной интеграцией.
