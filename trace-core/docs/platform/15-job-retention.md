# Хранение истории фоновых заданий

Реализована ручная очистка служебной истории завершённых Job. Автоматического удаления по расписанию нет. По умолчанию хранится 90 дней, выборка ограничена 100 заданиями (API/CLI максимум 500, срок 1–3650 дней).

Администратор в разделе «Организация и доступ» получает предварительный просмотр и скачивает JSON-план. GET `/api/v1/access/job-retention` не удаляет данные; HTTP-операции применения нет. Аналитик, наблюдатель и сервисные учётные записи доступа к этому административному маршруту не имеют.

План действует один час, содержит пространство, границу возраста, идентификаторы, итоговые состояния, время завершения и число связанных строк. При применении проверяются область, срок и актуальность кандидатов. Изменившийся статус, время завершения или число зависимостей прерывают всю транзакцию. Захват общего QueueControl сериализует операцию с очередью. Повтор того же плана в пределах срока действия возвращает already-applied.

Удаляются только выбранные Job и их Receipt, Heartbeat, RescanJob, Outbox, Attempt. Queued/running, недавние задания и задания с незавершённым Attempt исключены. Отмена распознаётся по terminalReason=cancelled. Scan, Finding, Project и PlatformAudit сохраняются. В аудит записываются системный оператор, SHA-256 плана, идентификаторы и счётчики; ошибка аудита откатывает удаление.

## Работа оператора

Сначала сделать резервную копию и явно выбрать нужную БД переменной TRACE_DATABASE_URL. Из каталога trace-core:

```powershell
.\.venv\Scripts\python.exe -m trace_api.retain_jobs --workspace default --days 90 --output plan.json
```

После проверки файла отдельная команда применяет именно этот план:

```powershell
.\.venv\Scripts\python.exe -m trace_api.retain_jobs --workspace default --apply-plan plan.json
```

CLI предназначен доверенному оператору с прямым доступом к БД. Файл не является криптографически подписанным разрешением. Выходной файл не перезаписывается. Без явного URL БД CLI прекращает работу, чтобы не выбрать старую trace.db случайно.

После очистки старый jobId больше не доступен, включая привязанный progress; сами результаты проверки остаются. Очистка резервных копий, логов и результатов сканирования в этот этап не входит. PostgreSQL в живом окружении не проверялся. На рабочей базе выполнен только предпросмотр, применение проверено на изолированных тестовых БД.

Проверки: 6 новых интеграционных тестов (права, границы, отмена, исключение активных, откат, сохранность результатов, повторное применение), полный набор backend, TypeScript, production build и 7 проверок API-клиента.
