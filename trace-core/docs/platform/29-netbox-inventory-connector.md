# Этап 5Г — операторский read-only сборщик NetBox

Реализован `tools/collect_netbox_inventory.py`: GET выбранной роли серверов из `/api/dcim/devices/` → новый JSON `trace.inventory/1` → существующий импорт инфраструктурной инвентаризации. Браузер и API TRACE не получают токен NetBox и не выполняют запросы к произвольным адресам. Подключение к реальному NetBox не настроено: проверка выполнена только на локальном HTTP-стенде и отдельной БД TRACE.

## Запуск

Оператор предварительно проверяет ID роли, содержащей только серверы. Сетевые устройства и VM в эту версию не входят. Одна регистрация источника TRACE соответствует неизменной паре «экземпляр NetBox + роль + область видимости учётной записи». При смене области или экземпляра создайте отдельный источник: числовые ID устройств уникальны только внутри экземпляра. Права токена ограничьте чтением выбранных объектов; сборщик не проверяет, что выданный токен лишён остальных прав.

Задайте `TRACE_NETBOX_TOKEN` через принятый в вашей среде способ передачи секрета в окружение процесса. Не включайте его в команду, JSON, репозиторий или имя файла. Пример из корня trace-core (адрес и ID — шаблоны, не выполненное подключение):

```powershell
.\.venv\Scripts\python.exe tools/collect_netbox_inventory.py --url https://netbox.example --server-role-id 7 --run-id netbox-20261018-01 --auth-scheme Bearer --output netbox-20261018-01.json
```

`--auth-scheme Token` — для v1 токена; `Bearer` — для v2. По умолчанию Token; формат выбирается явно, содержимое секрета не угадывается. Имя переменной можно изменить через `--token-env`. Поддерживается HTTPS origin без path/query/fragment/userinfo, с проверкой TLS средствами Python. HTTP разрешён только для localhost/127.0.0.1/::1 локального стенда. Развёртывания под URL-префиксом, пользовательские proxy-настройки и отключение проверки TLS не поддерживаются. Системные proxy-переменные не используются.

В TRACE: «Платформа» → «Инфраструктурная инвентаризация» → зарегистрировать отдельный источник → «Импортировать снимок инфраструктуры» → выбрать JSON → проверить и импортировать. Повторная доставка использует тот же файл; для нового наблюдения задайте новый run ID и новый файл. Файл никогда не перезаписывается. CLI возвращает 0 для complete и 2 для partial/error; при ошибке самого сбора JSON всё равно сохраняется для регистрации неуспешной попытки. При ошибке параметров/записи новый пригодный файл не гарантируется — проверьте stderr и наличие результата.

## Сведения и границы доверия

Внешний ID `netbox:device:<id>`, имя (или явно сформированное `NetBox device #<id>` при пустом имени), тип server, заявленная platform.name. Ответ обязан содержать тот же role.id, что выбран оператором. Tenant, site, serial, IP, custom fields и токен не экспортируются; tenant не выдаётся за владельца, site — за регион. Версия ОС не выводится из модели устройства. Исходный ответ целиком не сохраняется. Фильтр роли не доказывает, что каждый объект физически является сервером: это операторская классификация.

Пагинация offset/limit, сортировка id, до 100 полученных записей, не более 10 страниц и 1 МиБ на страницу. Таймаут сетевого чтения 5 секунд; бюджет 30 секунд проверяется между чтениями/страницами (одна блокирующая операция может завершиться позднее). Автоматических повторов нет. URL следующей страницы не используется для отправки токена; чужой origin/path и HTTP redirects отклоняются. Смещение вычисляется локально. Неверные записи, дубль ID, изменение count, несовпадение количества, отсутствие прогресса, предел объёма, недоступность и ошибки доступа не маскируются под complete. При сохранённых наблюдениях статус partial, без них — error. Сообщения ошибок фиксированы: тело ответа/секрет/исключение не попадают в JSON или диагностический вывод.

Complete означает только получение заявленного количества доступных этой учётной записи объектов выбранной роли. Это не транзакционный снимок NetBox: параллельные изменения с неизменным количеством могут остаться незамеченными. observedAt — начало локального сбора, не время изменения устройства и не подтверждение его доступности. Только GET: бизнес-объекты NetBox не изменяются; сам NetBox может обновлять время использования токена. Сборщик не запускает проверки безопасности и ничего автоматически не импортирует/удаляет в TRACE. Применяются прежние immutable intake, idempotency, scope и freshness.

## Проверка

10 автоматических проверок на локальном HTTP-сервере: mapping/фильтр/Token и Bearer, пагинация, partial после ошибки, 401/403/500, redirect без второго запроса, чужой next, плохие/повторные устройства и чужая роль, лимит при коротких страницах, пустой complete/несовпадение count, JSON/byte limits, отказ до сети при неверной конфигурации и существующем файле. Каждый результат проверяется действующей Pydantic-схемой TRACE.

Отдельная сквозная проверка запускает настоящий CLI: две страницы mock NetBox → файл → POST в изолированный API TRACE → два наблюдения → идемпотентный повтор 200. Все 42 таблицы рабочей БД неизменны. Тестовый API и HTTP-стенд остановлены. Реальная совместимость с конкретной версией/правами/прокси NetBox требует отдельного подключения и проверки.

Протокол сверялся с официальными источниками: [REST API NetBox](https://netbox.readthedocs.io/en/stable/integrations/rest-api/), [роли устройств](https://netboxlabs.com/docs/netbox/models/dcim/devicerole/). Следующий этап — закрепление конфигурации области источника и журнал запусков коннектора; расписание и серверное хранение секрета пока не реализованы.
