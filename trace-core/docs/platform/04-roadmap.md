# Единый план развития TRACE

Актуально на 19 октября 2026. История этапов и проверок сохранена в 04-ui-roadmap.md и тематических документах 06–36. Пункты ниже — зависимости общей платформы, не отдельные просьбы пользователю написать «продолжай».

| Пакет | Текущее состояние | Критерий готовности и зависимость |
|---|---|---|
| Архитектура и аудит | Документы и модель подготовлены | 00–03: исходный аудит, текущие ограничения, понятные границы модулей |
| Общие активы и связи | Работает ограниченный сценарий | Реестр/проект/находка, источник и основание связи, изолированные данные |
| Доступ и пространства | Работает для одной организации | Роли/команды/scoped CRUD и jobs; multi-tenant/SSO — отдельная проверка |
| Jobs и доказательства | Работают ограниченно | Durable queue, heartbeat/cancel/recovery; hash, HMAC, immutable receipts и history |
| Supply chain и инфраструктура | Работают ручной контекст и inventory | Сквозной commit→deployment snapshot, inventory freshness/compare/reconciliation; реальная CMDB ещё не подключена |
| Самостоятельный SAST | Интеграция реализована, реальный инструмент отсутствует | Установить реальный инструмент в отдельной среде, протестировать на разрешённой локальной цели, подтвердить версии и ошибки; не подменять mock-процессом |
| Case/governance workflow | Реализован первый сквозной контур | Event/detection→incident→risk→task/control/exception; readonly observation, roles, optimistic revision, audit, scoped links и UI |
| Реальные DevSecOps adapters | Открыто | DAST/secret/IaC/container/license adapters с локальными fixtures, coverage и redaction; отдельные вкладки уже есть |
| Мониторинг и данные | Открыто, cases не SIEM | Внешние SIEM/EDR/IAM/PAM/DLP read-only интеграции с явно заданными аккаунтами и scope; поток событий отдельно от SQLite registry |
| Политики и SLA | Частично | Gate и ручные решения есть; нужны versioned policy/control catalogue, измеренные SLA, независимые approvals и enforceable исключения с ограниченной областью |
| Эксплуатация | Открыто | Schedules, quotas, PostgreSQL/load/restore, Vault/KMS/SSO, внешние immutable audit и evidence/event retention |

До внешних подключений продолжать локальные контракты, связи, UI и негативные тесты. Не создавать ложный статус подключения, не запускать сторонние сканирования и изменения инфраструктуры без разрешённых целей. За промышленную готовность отвечает набор наблюдаемых проверок, а не число вкладок.
