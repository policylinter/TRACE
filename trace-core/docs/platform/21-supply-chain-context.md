# Контекст репозитория, сборки, артефакта и развёртывания

Добавлен trace.supply-chain/1 — неизменяемая операторская запись для активов build/artifact/deployment. Это первая реализация контекста поставки, не проверка Sigstore/SLSA и не CI-коннектор.

## Сценарий

1. Зарегистрировать активы repository, build, artifact и deployment в одном пространстве.
2. В карточке сборки зафиксировать repositoryAssetId, полный commitSha (40 или 64 lowercase hex), buildExternalId, observedAt с timezone и evidenceRef.
3. В карточке артефакта указать buildAssetId с уже зафиксированным контекстом, digest формата sha256:64hex и основание/время.
4. В карточке развёртывания указать artifactAssetId с контекстом, environment, deploymentExternalId и основание/время.

Сервер копирует в артефакт ID репозитория, SHA коммита и контрольную сумму контекста сборки. В развёртывание дополнительно копируются digest артефакта, ID сборки и контрольные суммы контекстов предыдущих звеньев. Они не берутся из произвольных полей клиента. Кнопки в UI позволяют перейти от развёртывания к сборке/артефакту/репозиторию.

Общий AssetLink остаётся ручной связью с текстовым основанием. Контекст поставки не создаёт таких связей автоматически и не приравнивает общую связь по проекту к присутствию уязвимости в развёртывании.

## API и целостность

GET `/api/v1/platform/assets/{assetId}/supply-chain` возвращает context:null, если запись не создана. Чтение ничего не записывает. POST того же маршрута принимает discriminated union по kind: build/artifact/deployment. Тип должен соответствовать активу, неизвестные поля отклоняются. Нужны существующие связанные активы корректного типа в том же пространстве; незаписанный upstream контекст даёт 409.

Результат содержит context, SHA-256 нормализованного JSON, recordedAt/By из сервера и verification=operator_declared. observedAt — заявленное время из основания; UI переводит datetime-local браузера в UTC. evidenceRef — текстовая ссылка/ID, её содержимое не загружается. Не передавать секреты и пароли.

Одна запись на assetId. Точный повтор возвращает прежнюю запись (200), первая регистрация — 201; другие данные того же актива — 409. Для следующей поставки нужен новый актив с новым внешним ключом. Это намеренно сохраняет историю, но исправление ошибочно заявленного контекста пока выполняется регистрацией нового актива, а не редактированием старого.

PK и обработка IntegrityError защищают конкурентный повтор. Регистрация и supply-chain.recorded audit коммитятся вместе; ошибка аудита откатывает запись. Повторы не дублируют аудит. Контекст защищён от ORM update/delete и bulk mutations; внешние ключи и before_flush проверяют связанные активы, область запроса задаёт сервер. Это не защита от прямого оператора SQL.

Писать может аналитик/администратор пространства, читать — также наблюдатель. Сервисный аккаунт с inventory:read читает контекст, но inventory:write не даёт права фиксировать контекст. Автоматические attestations сервисных коннекторов требуют отдельного доверенного контракта и пока не реализованы.

## Проверка и границы

Семь новых тестов: полная цепочка и pinned контексты/actor, чтение без записи, идемпотентность и конфликт, конкурентный повтор, строгая схема и типы, полный SHA, права/область/service read-only, откат аудита и неизменяемость. Полный backend suite — 130 тестов; TypeScript, build и 7 API-client smoke проверок проходят.

На изолированном стенде 8007 создана тестовая цепочка; в браузере открыто развёртывание с коммитом/digest/окружением и проверен переход к сборке. Производственные активы и находки не создавались и не менялись. Основной API обновляется после резервной копии и проверки, что два init_db сохраняют прежние строки.

Непроверенные свойства: содержимое blob действительно соответствует digest, commit существует в репозитории, сборка породила именно этот артефакт, артефакт исполняется в окружении, подпись доверена. Они не выводятся из наличия контекста. Нет связи произвольной находки с digest без дополнительных оснований; AppSec gate и ручные связи retest не меняются. Не реализованы webhook/CI authentication, artifact registry resolver, SBOM digest binding и attestation. PostgreSQL в живом окружении не проверялся.
